# SoDEX Alpha Launch

SoDEX Alpha Launch is a builder-first research-to-execution terminal for the SoSoValue x SoDEX hackathon.

The product is designed around one practical idea:

> turn research, news, and index signals into venue-aware execution plans on SoDEX.

Instead of stopping at dashboards, the app connects:

- `SoSoValue` for research, hot news, macro context, and index rails
- `SoDEX` for market data, account state, and real order-routing flows
- `Operator workflows` for drafting, staging, reviewing, and submitting execution ideas

## Product Thesis

Most hackathon demos show data.

This project tries to show decision-making:

- what to watch
- why it matters now
- how to size it
- how to route it on SoDEX
- how to prove the workflow honestly in front of judges

That is why the app includes live market pages, a decision log, staged order planning, wallet-linked venue reads, and an operator queue instead of only charts.

## What The Tool Does

### 1. Trade Copilot

Route: `/execution`

The execution desk is the main trade planning surface.

It uses SoDEX market data to show:

- spread
- visible depth
- estimated fills
- fee-aware cost
- market impact
- risk gating before live submit

It supports:

- paper routing
- live SoDEX order preparation
- server-signed flow
- browser-wallet EIP-712 signing flow
- loading execution drafts generated by other modules

### 2. Index Rebalance Executor

Route: `/sosovalue-indexes`

This module turns index or basket ideas into staged venue plans.

It calculates:

- target weights
- current paper exposure
- drift vs target
- rebalance delta
- staged slice plan for SoDEX

It can generate execution drafts that are then pushed into the shared operator queue.

### 3. News-to-Execution Alert Bot

Route: `/alerts`

This module reads live SoSoValue hot news and macro events, then converts them into an execution shortlist.

It includes a basic regime engine that labels the tape as:

- `Macro Event Risk`
- `Defensive Tape`
- `Risk-On Expansion`
- `Balanced Tape`

From that regime, it auto-generates:

- side bias
- execution mode (`LIMIT` or `MARKET`)
- staged slices
- rationale for why the draft exists

### 4. Operator Lab

Route: `/operator-lab`

This is the differentiator of the product.

Operator Lab acts like a shared execution inbox for the whole app:

- receives drafts from rebalance logic
- receives drafts from the news bot
- shows staged slices
- adds live SoDEX context for the focused draft
- helps the builder decide what should be routed next

### 5. Portfolio Live

Route: `/portfolio-live`

Reads live SoDEX account state by wallet:

- balances
- open orders
- trade rows
- fee rate
- account readiness
- API key readiness

It also computes live PnL attribution when the queried wallet has actual SoDEX fills or trades.
Wave 2 additions inside this screen:

- Smart Money Watch for custom peer wallets
- peer benchmark / trader scorecard
- mini leaderboard for best timing / best sizing / best discipline
- counterfactual PnL replay with skip-bad-trades overlay

### 6. Decision Log

Route: `/decision-log`

Every meaningful action can be traced:

- signal reason
- SoSoValue news snapshot
- macro context
- SoDEX spread and depth context
- risk gate result
- execution outcome
- counterfactual "if skipped" overlay against current live marks

This is useful both for judging and for builder transparency.

## Live vs Local Honesty

This repo intentionally mixes:

- `live external data`
- `builder-local state`
- `derived execution logic`

That distinction matters.

### Live data

Live data is fetched from SoSoValue or SoDEX for:

- market rows
- broad SoDEX token universe for heatmap / screener / execution surfacing
- orderbook and trade context
- hot news and featured stories
- macro events
- SoDEX account state
- fee-rate and account readiness

### Local persisted state

Some modules use browser-local persistence for operator workflow:

- watchlist
- paper trades
- alerts
- decision log
- execution drafts
- bot history

Those are intentionally local because they are part of the demo workflow, not claimed as venue-native records.

### Derived logic

Some values are strategy outputs, not direct exchange fields:

- staged order slices
- rebalance deltas
- regime classification
- execution draft rationale
- estimated fills when exact route is not submitted yet

The product tries to be explicit about that distinction.

## Demo Flow For Judges

If you are using this repo for a live buildathon demo, this is the cleanest flow:

1. Open `/launch`
2. Show the product thesis and live market surface
3. Open `/news-and-insights`
4. Show live SoSoValue tape and macro calendar
5. Open `/alerts`
6. Generate a news-driven execution draft
7. Open `/sosovalue-indexes`
8. Generate a rebalance draft
9. Open `/operator-lab`
10. Show that both workflows feed a shared execution queue
11. Open `/execution`
12. Load a draft into the Trade Copilot and show spread, depth, fee-aware checks, and live route readiness
13. Open `/portfolio-live`
14. Prove the wallet/account state is read honestly from SoDEX
15. Open `/decision-log`
16. Show explainability and provenance
17. Open `/diag`
18. End by proving the stack is alive

## Security Notes

- Keep `SODEX_API_PRIVATE_KEY` server-side only
- Do not expose private signing keys in client bundles
- Browser-wallet flow uses typed-data signing and should match the configured public key when required
- Server-side routes are used to keep credentials out of the browser

## Limitations

This is a hackathon build, so a few constraints are intentional:

- decision logs and drafts are browser-local, not database-backed
- some planning modules generate staged order plans rather than auto-submitting all slices
- real portfolio attribution depends on the queried wallet having actual SoDEX fills
- some execution analytics are derived from live market context rather than being official venue post-trade metrics

## Why This Project Is Different

The main difference is that the app does not stop at “insight surfaces”.

It creates a full operator loop:

- insight
- prioritization
- draft generation
- execution review
- venue-aware submit path
- attribution and log trail

That makes it more useful as a builder product than a standard crypto dashboard.
